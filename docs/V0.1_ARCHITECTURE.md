# ScanMaster AI V0.1 架构说明

## 架构原则

工程采用 MVVM + Clean Architecture。依赖只能由外向内，Domain 不依赖 SwiftUI、UIKit、Core Data、VisionKit、PDFKit 或 Core Image。

```text
Presentation (SwiftUI + ViewModel)
              ↓
Application (Use Cases)
              ↓
Domain (Entities + Protocols + Rules)
              ↑
Infrastructure (Framework Adapters)
```

`AppDependencyContainer` 是组合根，负责把协议实现注入用例和 ViewModel。界面层不直接访问数据库和磁盘。

## 层次职责

### Domain

- `ScannedDocument`：文档聚合根。
- `ScannedPage`：页面路径、顺序、旋转和滤镜元数据。
- `CapturedPage`：尚未持久化的页面输入。
- `DocumentRepository`：文档元数据仓储接口。
- `ImageEnhancing`、`PDFGenerating`、`DocumentFileManaging`：基础设施端口。
- `DocumentNamePolicy`、`PageOrderer`：可在纯 Swift 环境验证的领域规则。

OCR 字段和 tags 字段在模型中保留，但 V0.1 不读写 OCR 内容，也不开放标签 UI。

### Application

- `SaveScannedDocumentUseCase`：处理原图、保存原图/增强图、生成 PDF、写数据库；失败时清理未完成文件。
- `UpdateScannedDocumentUseCase`：保留聚合根身份，重新处理页面、重建 PDF 并清理已删除页面文件。
- `DocumentLibraryUseCase`：查询、重命名、删除、合并、拆分和文件 URL 转换。

### Infrastructure

- `DocumentScannerView`：封装 `VNDocumentCameraViewController`。
- `CoreImageEnhancer`：无第三方依赖的五种滤镜管线。
- `PDFGenerator`：使用 `UIGraphicsPDFRenderer` 生成 A4 PDF。
- `CoreDataStack`：程序化模型和 SQLite 持久化。
- `CoreDataDocumentRepository`：Core Data 与领域模型映射。
- `LocalDocumentFileManager`：应用支持目录中的原图、增强图和 PDF。

### Presentation

- Home：首页入口和最近文档。
- Editor：页面预览、滤镜、旋转、重拍、排序和保存。
- Documents：列表、PDFKit 预览、页面重新编辑、重命名、分享、合并、拆分和删除。

View 只负责渲染、绑定和导航；业务状态、异步工作和错误处理位于 ViewModel。

## 数据设计

Core Data 使用 SQLite 存储：

```text
CDDocument
  id, filename, typeRaw, createdAt, updatedAt,
  pdfPath, ocrText, tagsData
  └── pages (cascade)

CDPage
  id, documentID, originalImagePath, processedImagePath,
  order, rotationRaw, filterRaw
```

大图片不进入 SQLite，避免数据库膨胀。每份文档使用独立目录：

```text
Application Support/ScanMasterAI/Documents/<document-id>/
├── Images/<page-id>-original.jpg
├── Images/<page-id>-processed.jpg
└── <用户文件名>.pdf
```

## 一致性策略

- 保存失败：删除整个未完成文档目录，不写入元数据。
- 数据库写入发生在 PDF 成功生成之后。
- PDF 先写入目标目录中的 `.scanmaster-<UUID>.pdf`，渲染成功后再原子替换正式文件；渲染或写入失败时旧 PDF 保持不变，并清理临时文件。
- 重命名先移动 PDF，再写数据库；数据库失败时尝试回滚文件名。
- 页面重新编辑保留文档 ID、创建时间、类型、标签和 OCR 预留内容，数据库成功后再清理被删除页面。
- 删除先移除数据库记录，再尽力清理孤立文件。
- 页面顺序由连续的 `order` 值表达，读取时始终排序。

V1.5 前需要增加更完整的事务日志和孤立文件巡检，覆盖应用被系统强制终止的极端情况。

## 性能与内存

- VisionKit 在系统进程内完成捕获和初步矫正。
- 滤镜预览使用最长边 1,600 px；保存重新处理原始 JPEG。
- Core Image 不缓存中间结果；保存、更新和 PDF 渲染均按页建立自动释放池，避免 20 页高清任务同时保留多页图像对象。
- PDF 保存、合并、拆分和预览滤镜在后台队列执行。
- Core Data 上下文通过 `performAndWait` 保证队列安全。
- 文档列表只加载每份文档第一页作为缩略图；V1.5 将增加磁盘缩略图缓存和分页。

## 隐私与安全

- V0.1 无网络 SDK、广告 SDK和分析 SDK。
- 原图、增强图和 PDF 均位于应用私有沙盒。
- Privacy Manifest 声明不跟踪、不收集数据。
- 相机权限文案明确说明本地扫描用途。
- Face ID 与文件加密按路线图在 V4.0 接入；当前不能宣称文件已加密。
